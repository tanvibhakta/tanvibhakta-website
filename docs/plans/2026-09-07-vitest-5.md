# Vitest 5 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Upgrade vitest 3.2 → 5.0 in one jump, adding the explicit `vite` devDependency that vitest 5 requires as a peer.

**Architecture:** Vitest 5 made vite a required (non-optional) peer dependency; this project has no direct vite dep — Astro 5.18 brings `vite ^6.4.1` transitively, which satisfies vitest 5's range (`^6.4.0 || ^7 || ^8`) but doesn't count as a peer for pnpm. Without an explicit dep, pnpm auto-installs the newest allowed vite (v8) next to Astro's v6 — two vites, subtle breakage risk. So we pin an explicit `vite@6` devDependency that dedupes with Astro's copy (bump to 8 when the astro-7 track lands). Everything else in v4/v5's breaking lists (workspace→projects, browser mode, pools, coverage options, reporters) is unused here; the two behavior changes that touch us — `clearMocks` defaulting to true, and hoisted `vi.mock` throwing when not top-level — are both already satisfied by the existing test style (`mockReset()` in `beforeEach`, top-level mocks in `tests/feeds.test.ts` / `tests/collections.test.ts`).

**Tech Stack:** vitest 5.0.x, vite 6.4.x (explicit devDep). Node 24 satisfies vitest 5's engines (`^22.12 || ^24 || >=26`); @types/node 26 (from the trivial batch) satisfies its peer range.

**Branch/worktree:** `.worktrees/vitest-5`, branched from `main` after PR #119 merges. Independent of the eslint and trivial-batch tracks (runs any time after #119); do it BEFORE the astro-7 track so test tooling is settled under the riskiest upgrade.

### Task 1: Bump vitest, add explicit vite

**Files:**

**Step 1: Install**

```bash
cd /Users/tanvibhakta/Code/website/tanvibhakta.in/.worktrees/vitest-5
```

(`vite@6` rather than `@latest` is deliberate — the version must dedupe with Astro 5.18's bundled `vite ^6.4.1`; `@latest` would install v8 alongside it. Revisit when Astro 7 lands with vite 8.)


Expected: one vite 6.4.x serving both astro and vitest — not a 6.x AND an 8.x.

**Step 3: Verify vitest's peer is satisfied**

```bash

```

Expected: `no peer warnings`.

### Task 2: Run and triage

**Step 1: Run the suite (bare, never piped)**

```bash
pnpm test
```

Expected: 10 files / 101+ tests pass, same as on vitest 3. `vitest.config.ts` needs no changes — its explicit `exclude` overrides the (simplified) defaults, and `fileParallelism` survived both majors.

Triage guide if anything fails:
- **Unawaited async assertion** (`expect(...).resolves`/`rejects` without `await`): now a test failure instead of a warning. Fix: add `await`.
- **Mock call-count assertion failing**: `clearMocks` now defaults to true (history cleared before each test). A test asserting on calls made in a *previous* test was depending on leakage — fix the test, not the config.
- **Snapshot mismatch mentioning mock names**: `getMockName()` default changed in v4. Update the snapshot if that's all it is.
- Do NOT set `clearMocks: false` to force green — that re-hides inter-test leakage.
