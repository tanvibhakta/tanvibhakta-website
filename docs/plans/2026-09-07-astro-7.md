# Astro 7 Migration Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Upgrade astro 5.18 → 6 → 7 (with @astrojs/mdx → 8 and sharp → 0.35), preserving the markdown pipeline — heading anchors, paragraph anchors, and line breaks — whose plugins Astro 7's new default processor silently drops.

**Architecture:** Two-stage upgrade with a built-HTML diff gate at each stage. Stage 6 is nearly free (this site already uses the Content Layer API that survived both majors); its risks are Zod 4 and new `<Image>` crop/no-upscale defaults. Stage 7 is where the work is: Sätteri (Rust markdown processor) becomes the default and does NOT run remark/rehype plugins — `remark-breaks`, `rehype-slug`, `rehype-autolink-headings`, and our own `rehypeAnchors` would silently vanish from output while the build stays green. The fix: install `@astrojs/markdown-remark` (now a peer dep) and move the plugin config into `markdown.processor: unified({...})`. The v7 Rust compiler is also stricter (unclosed tags = build errors; JSX-style whitespace between inline elements), so templates get a visual pass. The HTML-diff gate turns every "silent" failure mode into a loud one.

**Tech Stack:** astro 7.3.x, @astrojs/mdx 8.x, @astrojs/markdown-remark 7.3.x (new explicit dep), sharp 0.35.x. Unchanged and already v7-compatible: @astrojs/rss 4.0.19, @astrojs/sitemap 3.7.4, astro-icon 1.2.0, prettier-plugin-astro 0.14.1, tailwind 4.3 (Rolldown keeps the Vite plugin API). Node ≥22.12 required — Node 24 everywhere ✓.

**Branch/worktree:** `.worktrees/astro-7`, branched from `main` AFTER the other three tracks merge (eslint-10, chore-majors, vitest-5) — this track goes last so the tooling under it is settled. If the vitest-5 track added `vite@6`, bump it here (`pnpm add -D vite@latest`) when astro 7 brings vite 8.

**Reference docs (read before starting):**
- https://docs.astro.build/en/guides/upgrade-to/v6/
- https://docs.astro.build/en/guides/upgrade-to/v7/

**Caution for the implementer:** the `unified()` processor import in Task 4 is written from research notes, not from a compiler-checked example — verify the exact import path and option shape against the v7 upgrade guide before typing it. When markdown output looks stale while iterating, delete `node_modules/.astro/data-store.json` — Astro's content cache survives `rm -rf dist`.
